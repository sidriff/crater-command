# Readability · v1 · blank rock, real chrome

The match view is a CRT globe with wire entities. This lab is the same
`PlanetView` path with **no match clutter** until a board paints entities.

## What's exposed

**Flat globe** — same `PlanetView` stack, but `flatTerrain: true`: constant-radius
sphere, no crater bowls, no height noise, no pass/rim paint. Entity placement
uses the same flat profile so buildings sit on the rock. Lighting, starfield,
FOW UVs, phosphor wire hull unchanged. No minerals or structures until a board
loads.

**Boards** — Blank · Identity grid · Contact · FOW edge · Clutter max.

**Camera** — elev, dist, optional nadir diagnostic. Defaults match live tactical
pose (`DEFAULT_DIST`, ~48° elev). Drag/zoom still work (same planet input).

**Scorecard** — kind / owner / role / motion / density / FOW / faction checks,
notes, JSON export + PNG screenshot for model iteration.

**Viewer race** lever — rebuilds the board with Ops / Blight / Mandate as player 0.

## What's deliberate, not a bug

- **No separate art path.** Entity chrome is match chrome; only the *terrain*
  is flattened so silhouette work isn't fighting bowls and ridges.
- **Flat is intentional.** Match relief is a separate concern (Globe lab later).
- **Nadir is diagnostic only.** Live play is oblique; don't overfit top-down.
- **Static snapshots** (no sim tick). Motion readability is judged from unit
  silhouettes and positions, not full AI pathing.
- **FOW edge board** uses partial `vision` arrays — same entity visibility rules
  as the game.

## Why this is the lab and not the game

Match mixes fog, hand, energy, bot pressure, and ten minutes of history. This
lab freezes one question: *from the player camera, can you tell what you're
looking at?* Boards are the unit of iteration for humans and models.

## Persistence

Active board, scorecard, and notes → `localStorage` key `crater-labs:readability`.
