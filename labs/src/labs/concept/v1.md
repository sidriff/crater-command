# Concept lab v1 — Operators wireframe art

Gallery of **generated** phosphor-wire concepts for Orbital Operators units and buildings. Not in-match meshes (see **Mesh** lab for those).

## Open

```
npm run lab
# → Concept in the picker, or:
/?lab=concept&concept=rover
```

Console: `ccLabs.openConcept("dome")` · `ccLabs.conceptFeedback()`

## Art brief

Simple wireframe matching in-game chrome:

- Pure black void background
- Black faces **occlude** internals (not see-through CAD)
- Thin phosphor green edge lines only
- No textures, ground, stars, or greeble
- Reference: `assets/operators/_wire_ref.png` (flyer style sample)

Regen prompt block lives in `catalog.ts` → `OPERATORS_STYLE`.

One deliberate exception: the **Habitat Dome** should stay see-through. The card
sells it as a fragile glass house and the faction's main soft spot; opaque faces
hide the thing that justifies its cost.

## Co-generation: producer + product (preferred)

**Do not invent a unit plate in isolation when a producer plate already stages it.**

The strong pipeline we landed on:

1. **Generate the producer first** with the product **parked on the plate**
   (depot + rover, bay + raider, airpad + interceptor, etc.). That forces a
   silhouette that fits the building’s aperture and scale.
2. **Extract the unit** as a second pass: `image_edit` with the producer art as
   the primary reference (+ `_wire_ref` for chrome). Prompt: *only the parked
   vehicle, no building*, same wire style, three-quarter on black.
3. **Archive** the previous main under
   `assets/operators/history/<id>/<session>.jpg` before overwriting.
4. Update `ConceptDef.subject` so later regens don’t drift off the co-gen pair.

Why it works: one identity, two crops. The unit stops looking like a different
faction’s craft. Raider ← Bay (2026-08) is the proof case.

Same rule for **Interceptor** (from Airpad) and **Bomber** (from Bomber Works)
when those unit plates need a real pass — seed from the building’s parked craft,
not from a generic “fighter” prompt.

## Two feedback channels

They're deliberately separate and never overwrite each other.

**Your verdict** — click a card, set keep / revise / reject, type notes. Lives in
`localStorage` (`crater-labs:concept`). Ephemeral, yours.

**Agent review** — a standing art-direction pass stored in the catalog itself, at
`catalog.ts` → `ConceptDef.review`. It's source, so it diffs, survives a cache
clear, and reads in the editor next to the thing it's about. Toggle it off with
the **Agent review** lever if you want a clean look at your own calls.

```ts
review: {
  verdict: "keep" | "revise" | "reject",
  keeps: string,           // what the plate already earns
  fixes: string[],         // changes, most important first
  mesh?: string,           // how it diverges from the shipped geo
}
```

Cross-plate findings that belong to no single card live in `ROSTER_NOTES`, and
surface both in the side panel and under any card they touch.

Current tally: **0 reject · 1 revise · 23 keep** (core regenerating for re-score;
command + logistics human-promoted keep). Regen queue lists remaining revises
worst-first.

## Handoff

**Copy feedback JSON** is a compact diff, not a full dump:

- `todo` — revise / reject, or any card with notes (work still needed)
- `promoted` — human **keep** where agent review was revise/reject (flip catalog)
- `keep` — silent keeps listed by `{ id, label }` (never a bare count)
- `tally` / optional `globalNotes`

Style, roster notes, production map, and agent `review` bodies stay in source —
open the catalog when a `todo` id needs them.
